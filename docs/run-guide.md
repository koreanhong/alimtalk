# 실행 가이드

API 키 설정부터 서버 실행, 테스트, 에러 확인까지의 명령을 모은 문서다. 키 값은 이 문서와 저장소 어디에도 적지 않는다.

## 1. 실제 Claude 모드로 실행

**모든 단계를 같은 터미널 창 하나에서** 실행한다. 키는 그 창 안에서만 유효하다.

```bash
# 0) 이미 떠 있는 서버가 있으면 그 창에서 Ctrl + C 로 끈다 (8080 포트를 비워야 함)

# 1) 프로젝트 폴더로 이동
cd ~/Projects/alimtalk

# 2) API 키 설정 — 실행 후 키를 붙여넣고 Enter (화면에 보이지 않는 것이 정상, 셸 히스토리에 남지 않음)
read -s ANTHROPIC_API_KEY && export ANTHROPIC_API_KEY

# 3) 키가 들어갔는지 확인 (키 값은 표시되지 않음)
[ -n "$ANTHROPIC_API_KEY" ] && echo "키 설정됨 (길이: ${#ANTHROPIC_API_KEY})" || echo "키 없음"

# 4) 실제 호출 테스트 1회 (비용 발생) — BUILD SUCCESSFUL 이면 정상
LIVE_LLM_TEST=true ./gradlew test --tests '*ClaudeLlmClientLiveTest'

# 5) 서버 실행 (로그를 build/live-run.log 에도 저장)
./gradlew bootRun 2>&1 | tee build/live-run.log
```

- 서버가 뜬 뒤 http://localhost:8080 에 접속한다.
- 서버 시작 시 `ANTHROPIC_API_KEY(또는 ANTHROPIC_AUTH_TOKEN) 환경변수가 없습니다` 경고가 **나오지 않아야** 정상이다.
- 4단계가 실패하면 원인은 `build/reports/tests/test/index.html`에서 볼 수 있다.

### 사용량 기록 (`logs/llm-usage-v2.csv`)
- Claude 요청 1건(챗봇 대화 1턴 또는 한 번에 채우기 1회)마다 한 줄씩 기록된다(작성·질문·규칙 위반·거절·오류 모두). 엑셀에서 바로 열 수 있다.
- 항목: 시각, 결과, 시도 횟수, 소요(ms), 입력·출력·캐시 읽기·캐시 저장 토큰(재생성 포함 합계), 추정비용(USD), 모델, effort, 카테고리, 메시지 유형, 강조 유형, 요청 문장(마지막 발화), 모드(NEW/POLISH), 대화턴수
- 결과 값: `SUCCESS`(작성), `ASK`(질문), `RULE_VIOLATION`(재생성 후에도 위반), `AD_CONTENT`(광고 거절), `UNCLEAR`(한 번에 채우기의 되묻기), `ERROR_*`(오류)
- 날짜별 합계: 같은 폴더의 `llm-usage-v2-summary.csv`(날짜별 1줄 + 맨 아래 `합계`). 요청 수, 결과별 건수(`UNCLEAR`·`ERROR_*`는 `기타`), 시도, 토큰 4종, 추정비용 합계. 기록할 때마다 원본 전체에서 다시 계산한다.
- 대화형 이전 기록은 `logs/llm-usage.csv`(열이 적은 이전 형식)에 남아 있다.
- 비용은 `application.yml`의 `alimtalk.usage-log.price` 단가(100만 토큰당 USD)로 계산한 **추정치**다. 실제 청구 금액은 Claude Console의 사용량·비용 화면에서 확인한다.
- 파일은 git에 포함되지 않는다(`logs/`). 경로는 `alimtalk.usage-log.path`로 바꿀 수 있다.

## 2. 가짜 LLM 모드로 실행 (키 없이, 비용 없음)

```bash
cd ~/Projects/alimtalk
SPRING_PROFILES_ACTIVE=fake-llm ./gradlew bootRun
```
- 화면 흐름만 확인할 때 쓴다. 응답은 마지막 발화의 단어로 정해진다(자세한 규칙: `FakeLlmClient` 클래스 주석).
  - "광고"·"홍보" → 거절 / "생성해줘" → 유형 질문 + 선택지 / 시작 선택지(첫 발화가 "… 안내 메시지") → 넣을 정보 질문 + 선택지
  - "다듬"·"정중" → 다듬기 결과(본문 앞에 "[다듬음] ", 폼의 유형·부가정보·아이템리스트 유지) / "다듬"+"위반" → 규칙 위반 다듬기 결과 / "위반" → 1,100자 본문(규칙 위반) / "경고" → 경고가 붙는 초안 / 그 외 → 주문완료 템플릿
  - "아이템" → 아이템리스트형 초안 / "채널" → 채널추가형 초안 / "이미지" → 이미지형 초안

## 4. 에러 확인 방법

챗봇에 오류 말풍선이 나오면 아래 순서로 확인한다.

1. **서버를 띄운 터미널 창**(또는 `build/live-run.log`)에서 `WARN` 줄을 찾는다.
2. **브라우저**: F12 → Network → `chat` → Response의 `reason` 값(`LLM_ERROR`, `TIMEOUT`, `BAD_REQUEST` 등). 자세한 원인은 서버 로그에만 있다.
3. "대화가 길어졌어요"는 오류가 아니다. 내가 보낸 말이 10번이 되면 나오며, [새 대화]로 다시 시작한다.

| 서버 로그 | 의미 | 해결 |
|---|---|---|
| `ANTHROPIC_API_KEY(또는 …) 환경변수가 없습니다` (시작 직후) | 키를 넣지 않은 창에서 서버를 띄움 | 1장 순서대로 같은 창에서 다시 실행 |
| `LLM API 오류: status=401` | 키가 틀림 | 키 확인 |
| `LLM API 오류: status=400` | 크레딧 부족 또는 요청 형식 문제 | Claude Console에서 크레딧 확인 |
| `LLM API 오류: status=403` / `404` | 권한 없음 / 모델(`claude-opus-5-5`)을 쓸 수 없는 계정 | Claude Console에서 계정 상태 확인 |
| `LLM API 오류: status=429` / `529` | 호출량 제한 / Claude 서버 혼잡 | 잠시 후 재시도 |
| `템플릿 생성 실패: kind=TIMEOUT` | 응답 지연(호출당 60초, 전체 120초 초과) | 다시 시도 |

## 5. 자연어 테스트 케이스 (한 번에 채우기 API)

화면은 이제 챗봇(`/api/templates/chat`)을 쓰므로, 이 표는 남아 있는 한 번에 채우기 API(`POST /api/templates/generate`) 기준이다(2026-11-13 실행 결과 15/15). 같은 문장을 챗봇 첫 발화로 넣어도 되지만, 챗봇은 정보가 부족하면 되물으므로 결과가 다를 수 있다. 1번은 이제 API에서도 되묻기(UNCLEAR)가 나올 수 있다.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 주문 관련 메시지 세팅해줘 | 구매·구매완료로 작성 + "주문 완료 안내로 가정했습니다" 경고(노란색) |
| 2 | 주문 취소되면 환불 금액 알려주는 메시지 | 구매·구매취소 |
| 3 | 배송 시작됐다고 알려주는 메시지 만들어줘 | 배송·배송상태, 택배사·송장번호 변수 |
| 4 | 병원 진료 예약 확정 안내 메시지 | 예약·예약완료 |
| 5 | 회원가입 환영 메시지 | 회원·회원가입 |
| 6 | 회원가입 인증번호 보내는 거 | 회원·인증, 보안 템플릿 체크 |
| 7 | 결제 금액이 크게 보이게 주문 완료 안내 | 강조 유형 강조 표기형(제목에 금액) |
| 8 | 고객센터 전화번호도 아래에 넣어서 주문 안내 | 메시지 유형 부가정보형(부가정보에 고객센터) |
| 9 | 이번 주말 할인 행사 홍보해줘 | 광고라서 작성 불가 안내 |
| 10 | 장바구니에 담아둔 상품 사라고 알려줘 | 광고(카카오 발송 불가 예시) 안내 |
| 11 | 신상품 출시 알림 보내줘 | 광고 안내(판단이 갈릴 수 있음) |
| 12 | 세팅해줘 | 무엇을 안내할지 알 수 없어 되묻는 안내 |
| 13 | 채널 추가 버튼 넣은 주문 안내 | 채널추가형(부가정보가 있으면 복합형)으로 작성, 광고 거절 아님 |
| 14 | 이미지 넣은 배송 안내 | 이미지형으로 작성(강조 제목 없음), 이미지 파일은 직접 올림 |
| 15 | 이용약관 변경 내용을 전부 자세히 안내하는 메시지 | 재생성(시도 2~3회) 또는 규칙 위반 안내가 나올 수 있음 |

## 6. 챗봇 대화 시나리오 (실제 Claude, 비용 발생)

1장 순서로 서버를 띄운 뒤 http://localhost:8080 에서 왼쪽 아래 💬 버튼으로 챗봇을 연다. 시나리오마다 [새 대화]로 시작한다(6번만 1번 대화에서 이어서). 폼 조작은 챗봇이 아니라 폼에서 직접 한다. Claude 문구는 매번 달라질 수 있으며 "기대 결과"는 설계상 기준이다. 끝나면 `logs/llm-usage-v2.csv`의 결과·모드·대화턴수·추정비용을 함께 본다.

| # | 하는 일 | 기대 결과 | 확인할 점 |
|---|---|---|---|
| 1 | 시작 선택지 [배송 시작] 클릭 → 질문의 선택지 하나 클릭(또는 직접 입력) | 질문 1~2번 뒤 배송 시작 안내 초안. [적용] 시 폼·미리보기 채워짐 | 질문에 선택지 버튼이 나오는지, CSV 결과 `ASK` → `SUCCESS`, 모드 NEW |
| 2 | "고객센터 번호 1588-0000 넣어서 주문 완료 안내 만들어줘" 입력 | 질문 없이(또는 1번) 바로 초안, 부가정보형에 고객센터 | 정보가 충분하면 되묻지 않는지 |
| 3 | "새 메시지 하나 만들어줘" → 질문마다 선택지 대신 입력창에 "잘 모르겠어요"를 3번 입력(예시 폼이 있으면 "세팅해줘"는 다듬기로 판단됨) | **4번째 응답은 질문이 아니라 초안**. 초안이 나오면 끝 | 오류 말풍선·서버 `WARN` 없음. CSV 4번째 줄이 `SUCCESS` (대화 끝에 강제 작성 지시를 붙이는 방식이 실제 API에서 통하는지 처음 확인하는 항목) |
| 4 | 폼 맨 아래 **[예시로 초기화]** 버튼 → 챗봇 [지금 폼 다듬기] 클릭(또는 "지금 폼을 더 정중하게 다듬어줘") | 다듬은 결과를 먼저 보여 주고 [적용]/[취소]. [적용] 시 글만 바뀌고 버튼·예시값 유지 | CSV 모드 `POLISH`. 새로 만들기로 잘못 판단하면 덮어쓰기 확인 창이 뜸 |
| 5 | 폼에서 메시지 유형 **복합형** 선택, 부가정보에 "문의: 고객센터 1588-0000" 입력 → "다듬어줘" → [적용] | 복합형 유지, 부가정보가 비지 않고 남음(문구는 다듬어질 수 있음), 채널추가 버튼 유지. 말풍선에 "메시지 유형: … → …" 줄이나 유형 변경 경고가 없어야 함 | 유형이 바뀌거나 부가정보가 사라지면 실패(이제 서버가 아니라 Claude가 유지) |
| 6 | 1번 결과를 [적용]한 상태에서 후속 선택지(예: [고객센터 안내 추가]) 클릭 | 지금 템플릿에 고객센터 안내가 더해짐(새 템플릿을 처음부터 만들지 않음) | CSV 모드(POLISH 기대, Claude 판단), 다른 종류 템플릿으로 바뀌지 않는지 |
| 7 | "이번 주말 할인 행사 홍보해줘" | 광고라 알림톡으로 보낼 수 없다는 안내 | CSV 결과 `AD_CONTENT` |
| 8 | "아이템리스트로 주문 완료 안내 만들어줘" | 아이템리스트형: 헤더, 항목 2~10개, (금액이 있으면) 요약. 미리보기에 목록 표시 | 재생성 횟수(CSV 시도), 요약 금액이 "원원"처럼 겹치지 않는지 |
| 9 | "채널 추가 넣어서 배송 시작 안내 만들어줘" | 채널추가형(부가정보가 있으면 복합형), 미리보기에 채널 추가 버튼·문구 | 광고 거절(AD_CONTENT)로 가지 않는지 |
| 10 | "이미지형으로 배송 시작 안내 만들어줘" | 이미지형, 말풍선에 "이미지는 폼에서 올려 주세요." | 강조 제목·보조 문구가 비어 있는지 |
| 11 | 폼을 아이템리스트형·채널추가형으로 만들어 둔 뒤 "더 정중하게" → [적용] 전에 말풍선 확인 | 유형 유지(유형 변경 줄·경고 없음), 항목은 의미 그대로 문장만 다듬음 | 요청 안 했는데 유형이 바뀌면 실패 |
| 12 | "여러 상품 주문 완료 안내 만들어줘" | 기본형·부가정보형으로 작성하고, 아이템리스트형은 후속 선택지(예: "아이템리스트로 바꾸기")로만 제안 | 요청 안 했는데 바로 아이템리스트형이면 실패 |

## 주의

- 새 터미널 창을 열면 키가 사라진다. 그때는 1장 2단계부터 다시 한다.
- 키는 대화창(Claude Code 포함), `!` 명령, 셸 히스토리에 남기지 않는다. `export ANTHROPIC_API_KEY=키` 형태로 직접 입력하면 `~/.zsh_history`에 저장되므로 쓰지 않는다.
- 이미 히스토리에 남았다면: `sed -i '' '/ANTHROPIC_API_KEY=/d' ~/.zsh_history` (터미널 창을 모두 닫은 뒤 실행)
