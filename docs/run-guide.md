# 실행 가이드

API 키 설정부터 서버 실행, 테스트, 에러 확인까지의 명령을 모은 문서다. 키 값은 이 문서와 저장소 어디에도 적지 않는다.

## 1. 실제 Claude 모드로 실행

**모든 단계를 같은 터미널 창 하나에서** 실행한다. 키는 그 창 안에서만 유효하다.

```bash
# 0) 이미 떠 있는 서버가 있으면 그 창에서 Ctrl + C 로 끈다 (8080 포트를 비워야 함)

# 1) 프로젝트 폴더로 이동
cd ~/Projects/alimtalk

# 2) API 키 설정 — 실행 후 키를 붙여넣고 Enter (화면에 보이지 않는 것이 정상, 셸 히스토리에 남지 않음)
read -s ANTHROPIC_API_KEY && export ANTHROPIC_API_KEY

# 3) 키가 들어갔는지 확인 (키 값은 표시되지 않음)
[ -n "$ANTHROPIC_API_KEY" ] && echo "키 설정됨 (길이: ${#ANTHROPIC_API_KEY})" || echo "키 없음"

# 4) 실제 호출 테스트 1회 (비용 발생) — BUILD SUCCESSFUL 이면 정상
LIVE_LLM_TEST=true ./gradlew test --tests '*ClaudeLlmClientLiveTest'

# 5) 서버 실행 (로그를 build/live-run.log 에도 저장)
./gradlew bootRun 2>&1 | tee build/live-run.log
```

- 서버가 뜬 뒤 http://localhost:8080 에 접속한다.
- 서버 시작 시 `ANTHROPIC_API_KEY(또는 ANTHROPIC_AUTH_TOKEN) 환경변수가 없습니다` 경고가 **나오지 않아야** 정상이다.
- 4단계가 실패하면 원인은 `build/reports/tests/test/index.html`에서 볼 수 있다.

## 2. 가짜 LLM 모드로 실행 (키 없이, 비용 없음)

```bash
cd ~/Projects/alimtalk
SPRING_PROFILES_ACTIVE=fake-llm ./gradlew bootRun
```
- 화면 흐름만 확인할 때 쓴다. 응답은 고정이다: 요청에 "광고" → 거절, "위반" → 1,100자 본문(규칙 위반), 그 외 → 주문완료 템플릿.

## 3. 테스트

```bash
# 서버 자동 테스트 (실제 Claude 호출 테스트는 건너뜀)
./gradlew test

# 화면 자동 점검: 가짜 LLM 서버를 8081에 띄운 뒤 다른 창에서 실행
SPRING_PROFILES_ACTIVE=fake-llm ./gradlew bootRun --args='--server.port=8081'
src/test/ui/verify.sh
```
- 화면 자동 점검 설명: `src/test/ui/README.md`

## 4. 에러 확인 방법

화면에 "템플릿 생성 중 오류가 발생했습니다"가 나오면 아래 순서로 확인한다.

1. **서버를 띄운 터미널 창**(또는 `build/live-run.log`)에서 `WARN` 줄을 찾는다.
2. **브라우저**: F12 → Network → `generate` → Response의 `reason` 값(`LLM_ERROR`, `TIMEOUT` 등). 자세한 원인은 서버 로그에만 있다.

| 서버 로그 | 의미 | 해결 |
|---|---|---|
| `ANTHROPIC_API_KEY(또는 …) 환경변수가 없습니다` (시작 직후) | 키를 넣지 않은 창에서 서버를 띄움 | 1장 순서대로 같은 창에서 다시 실행 |
| `LLM API 오류: status=401` | 키가 틀림 | 키 확인 |
| `LLM API 오류: status=400` | 크레딧 부족 또는 요청 형식 문제 | Claude Console에서 크레딧 확인 |
| `LLM API 오류: status=403` / `404` | 권한 없음 / 모델(`claude-opus-5-5`)을 쓸 수 없는 계정 | Claude Console에서 계정 상태 확인 |
| `LLM API 오류: status=429` / `529` | 호출량 제한 / Claude 서버 혼잡 | 잠시 후 재시도 |
| `템플릿 생성 실패: kind=TIMEOUT` | 응답 지연(호출당 60초, 전체 120초 초과) | 다시 시도 |

## 5. 자연어 테스트 케이스

Claude가 매번 새로 작성하므로 문구는 달라질 수 있다. "기대 결과"는 설계상 기준이다. 화면의 "시도 N회", 경고(노란색), 걸린 시간도 함께 본다.

| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 주문 관련 메시지 세팅해줘 | 구매·구매완료로 작성 + "주문 완료 안내로 가정했습니다" 경고(노란색) |
| 2 | 주문 취소되면 환불 금액 알려주는 메시지 | 구매·구매취소 |
| 3 | 배송 시작됐다고 알려주는 메시지 만들어줘 | 배송·배송상태, 택배사·송장번호 변수 |
| 4 | 병원 진료 예약 확정 안내 메시지 | 예약·예약완료 |
| 5 | 회원가입 환영 메시지 | 회원·회원가입 |
| 6 | 회원가입 인증번호 보내는 거 | 회원·인증, 보안 템플릿 체크 |
| 7 | 결제 금액이 크게 보이게 주문 완료 안내 | 강조 유형 강조 표기형(제목에 금액) |
| 8 | 고객센터 전화번호도 아래에 넣어서 주문 안내 | 메시지 유형 부가정보형(부가정보에 고객센터) |
| 9 | 이번 주말 할인 행사 홍보해줘 | 광고라서 작성 불가 안내 |
| 10 | 장바구니에 담아둔 상품 사라고 알려줘 | 광고(카카오 발송 불가 예시) 안내 |
| 11 | 신상품 출시 알림 보내줘 | 광고 안내(판단이 갈릴 수 있음) |
| 12 | 세팅해줘 | 무엇을 안내할지 알 수 없어 되묻는 안내 |
| 13 | 채널 추가 버튼 넣은 주문 안내 | 기본형·부가정보형으로만 작성, 버튼·채널추가는 직접 설정 |
| 14 | 이미지 넣은 배송 안내 | 이미지 없이 작성 |
| 15 | 이용약관 변경 내용을 전부 자세히 안내하는 메시지 | 재생성(시도 2~3회) 또는 규칙 위반 안내가 나올 수 있음 |

## 주의

- 새 터미널 창을 열면 키가 사라진다. 그때는 1장 2단계부터 다시 한다.
- 키는 대화창(Claude Code 포함), `!` 명령, 셸 히스토리에 남기지 않는다. `export ANTHROPIC_API_KEY=키` 형태로 직접 입력하면 `~/.zsh_history`에 저장되므로 쓰지 않는다.
- 이미 히스토리에 남았다면: `sed -i '' '/ANTHROPIC_API_KEY=/d' ~/.zsh_history` (터미널 창을 모두 닫은 뒤 실행)
